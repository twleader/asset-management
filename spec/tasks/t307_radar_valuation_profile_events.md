# [t307] 交易雷達估值合成、資產輪廓、公開資訊市場與未來配息

**對應 Requirements:** Requirement 65（所有當時可得且不重複的估值、財報、資產輪廓與事件資訊）
**前置任務:** t292（基本面 observation）、t293–t296（美股與分頁）、t309（evidence groups）
**Liquibase changesets:** `v1.94.0-radar-event-observations.sql`, `v1.96.0-radar-market-observations.sql`, `v1.97.0-radar-dividend-provider-width.sql`, `v1.98.0-radar-dividend-same-day-amounts.sql`, `v1.99.0-radar-dividend-event-identity.sql`, `v1.100.0-radar-dividend-fetch-attempt.sql`

## 背景

`stock_valuation_daily` 已保存 PE、PB 與股息殖利率，但 `FundamentalAnalysisService` SELECT/record 只讀 PE。近似 ROE 以 TTM 淨利除最新期末權益；EPS 前期 TTM<=0 時直接 null，漏掉虧轉盈/盈轉虧。`Stock` 已有 `stock_style`／`bond_term`，規則只分 EQUITY/BOND。`PublicInfoEvidenceResolver` 只允許 TW region，使美股代號無法使用 US region 證據。`stock_dividend_history` 是以事件鍵覆寫的 normalized current-state 表，只有 mutable `updated_at`；它可供目前 UI 與歷史價格還原，但不能證明某個未來事件在歷史 decision instant 當時已知，故不得直接作歷史事件證據。

## 要做什麼

- [ ] **307.1 單一 valuation composite。** `ValuationRow` 同時讀 `pe_ratio/pb_ratio/dividend_yield_pct/pe_loss_flag`，每個 component 只使用同 provider、`source_available_at/observed_at<=decisionInstant`、最新 observation fresh 且自身有效歷史樣本>=250。DB 的 `*_pct` 一律以百分點保存（例如 4.0 代表 4%），adapter 若收到比例 0.04 必須在邊界轉成 4.0 且只准轉一次；style threshold 與 percentile 全部使用同一百分點單位。PE/PB contribution=`clamp(-(percentile-50)/30)`；殖利率 contribution 只取 `max(0, clamp((percentile-50)/30))`，不得因低殖利率扣成長股分。可信 `pe_loss_flag=true` 時 composite=-1；EPS/ROE severe 或持續虧損時殖利率 component=null，防止 yield trap。可用 components 平均成一個 `valuationContribution`，占用 V12 原 PE 權重，禁止新增三份完整權重。API 揭露三個 value/percentile/provider/asOf 與 composite coverage。
- [ ] **307.2 ROE 平均權益與 fallback 信心。** TTM ending equity 取最近季度，beginning equity 取同 provider 前四季的期末權益；兩者皆正時 denominator=(begin+end)/2。beginning 缺漏時可沿用 latest equity，但 `roeApproximationFallback=true` 並使 FINANCIAL evidence group 的 available weight 乘 0.75；不得跨 provider 拼接。測試涵蓋平均權益、fallback、任一非正與跨來源。
- [ ] **307.3 EPS turnaround。** recent/prior TTM 都正才計算百分比 YoY；recent>0 且 prior<=0 => `TURNAROUND` contribution +1；recent<=0 且 prior>0 => `TURNED_LOSS` -1；兩者<=0 => `PERSISTENT_LOSS` -1。輸出 `epsTrendType`，仍只佔 EPS 原權重。構造測試須證明負基期不再全數 null。
- [ ] **307.4 Strict 資產輪廓接線。** production/backtest 共用不可變 `AssetProfile`，不得直接用既有 unknown→MID 的 `classifyBondTerm()` 或持股殖利率 style 入口。asset class 依 override→code/name rule；bondTerm 依 override→名稱明確 SHORT/MID/LONG，否則 UNKNOWN；stockStyle 依 override→具名高股息 ETF→decision-time 公開 valuation yield 與全域 threshold，資料缺漏為 UNKNOWN。source 值域 `OVERRIDE|CODE_RULE|NAME_RULE|PUBLIC_VALUATION|MARKET_DEFAULT|UNKNOWN`。輪廓只決定 factor applicability 與回測分層；禁止讀成本、持股配息率、配置、可用資金或個人風險。BOND UNKNOWN term 不得進 rate；INCOME 可用 dividend evidence；GROWTH 不因低 yield 扣分。
- [ ] **307.5 Public info market-aware。** `PublicInfoEvidenceResolver.resolve/resolveFromRows/isVisible` 接收 market；台股允許 region TW/null，美股允許 US/null，其他 market 無證據。代號仍使用英數邊界、名稱/產業仍完整片語；news category 仍只顯示、不作 sentiment score。測試加入同代號跨 region 隔離、null global、US 美股命中與 TW 不誤入。
- [ ] **307.6 Append-only 完整配息 snapshot。** `v1.94.0-radar-event-observations.sql` 建三張正規化表；`v1.97.0` 將 snapshot provider 與 normalized history source 擴至 `VARCHAR(128)` 以容納 endpoint-set provenance；`v1.98.0` 使 normalized current-state 的同日不同 cash/stock amount 可並存；`v1.99.0` 保存 canonical `event_key` 與完整 payment identity；`v1.100.0` 增加 nullable-scope fetch-attempt audit。fetch adapter 同步把現有 `DividendFetchResult` 擴成 typed `status=COMPLETE|EMPTY_COMPLETE|PARTIAL|FAILED`、`scopeFrom/scopeTo/provider/sourceAvailableAt/errorReason/sourceUrls`，不得把例外吞成與「成功查無事件」相同的 EMPTY；TWSE/TPEx、FinMind dataset pair、Nasdaq daily、Yahoo chart endpoint manifest 必須沿 scope→result→snapshot 保存。
  - `stock_dividend_snapshot(id bigint identity pk,stock_code varchar(32),market varchar(16),provider varchar(128),scope_from date,scope_to date,source_url text,content_hash varchar(64),created_at timestamptz,unique(stock_code,market,provider,scope_from,scope_to,content_hash))`；provider 寬度由 `v1.97.0` 擴至 128；scope 必須涵蓋 fetch 宣稱的完整期間。
  - `stock_dividend_snapshot_event(id bigint identity pk,snapshot_id bigint fk,event_key varchar(64),year int,ex_dividend_date date,cash_dividend numeric(18,6),stock_dividend numeric(18,6),cash_payment_date date,stock_payment_date date,source_available_at timestamptz null,unique(snapshot_id,event_key))`。
  - `stock_dividend_fetch_observation(id bigint identity pk,snapshot_id bigint fk,observed_at timestamptz not null,status varchar(16) not null,complete boolean not null,scope_from date not null,scope_to date not null,source_available_at timestamptz null,error_reason text null,unique(snapshot_id,observed_at))`。只有 `status IN (COMPLETE, EMPTY_COMPLETE) AND complete=true` 且 scope 真正涵蓋宣稱期間的抓取才是 resolver authoritative observation；內容相同時重用 snapshot/event rows，只新增 fetch observation 以證明 freshness。`FAILED`、`PARTIAL`、provider timeout 或 invalid/null scope 必須保留 error/status 稽核，但不得建立可供 resolver 選取的成功 observation。
  - canonical content hash 先把每個事件依 `year|exDate-or-NULL|cash|stock|cashPay-or-NULL|stockPay-or-NULL` 固定格式，再按該字串排序後雜湊；event_key 為單列 canonical hash。這些 hash 是 immutable snapshot 去重/audit 的刻意衍生鍵，不進評分。
- [ ] **307.6.1 改期、取消與 current-state。** external-materials `DividendSnapshotStore` 只追加 immutable snapshot/event/fetch-observation；backend `DividendCurrentStateProjectionService` 每次維護 normalized `stock_dividend_history` 的 ACTIVE/CANCELLED current-state。v1.94 為該表加 `event_status varchar(16) not null default 'ACTIVE'`，v1.99 再保存 snapshot `event_key` 與完整金額／付款日 identity。完整新 snapshot scope 內未再出現、且在 observation 當時尚未發生的舊 future event 標 `CANCELLED`；同日金額或付款日修訂表現為舊事件 cancelled＋新事件 active；provider A→B 的相同 canonical event key 更新同一列。已發生事件不得因供應端查詢視窗滑動而取消；PARTIAL historical evidence 不得復活已被完整快照 tombstone 的列。價格還原只讀 ACTIVE/已實現事件。snapshot 模型不需跨 batch 猜 source event id；resolver 永遠選一個完整 snapshot，故日期改動與消失語意唯一。
- [ ] **307.6.2 Decision-time 查詢。** provider eligibility 與 precedence 固定，**不得以跨 provider 的 observedAt 全域最大值覆蓋優先序**：台股先合併 TWSE/TPEx 官方 endpoint，只有存在 `status IN (COMPLETE, EMPTY_COMPLETE) AND complete=true`、`observed_at<=decisionInstant`、scope 完整涵蓋 `[decisionDate,decisionDate+45 calendar days]` 且 `knownAt<=decisionInstant` 的官方 observation 才算官方可用；官方沒有這種完整可見 observation 才 fail over 到 FinMind（兩個 dataset 先後屬同一 provider，結果合成一個完整 scope）。美股先 NASDAQ，只有 NASDAQ 不可用才選 Yahoo Finance。選定 provider 後只在該 provider 內取 decision instant 前最新完整 observation，再取其單一 snapshot；不得每個 provider 各取一份再合併。官方後來恢復時，下一個 decision scope 重新回到官方；fallback 期間只由選定 provider 的完整 snapshot 觸發 current-state reconciliation，不得用另一 provider 的 partial/failed snapshot 取消事件。`FAILED`、`PARTIAL`、provider timeout 或 invalid/null scope 非成功完整 scope，不得觸發取消。event knownAt=`max(observed_at,source_available_at if present)`，且須 `knownAt<=decisionInstant`；來源無可靠公告時間時 basis=`OBSERVED`。同 snapshot 內找 `ex_dividend_date>decisionDate`、正 cash/stock 的最近事件，計未來 5/20 個該市場 session。回 metadata/source/knownAt/basis。事件只進 PUBLIC_EVENT/downside/reasons，不加 opportunity。回測不得由 current-state 表倒推已知事件；總報酬還原才讀 finalized ACTIVE history。
- [ ] **307.7 Typed 市場候選資訊與可得邊界。** `v1.96.0-radar-market-observations.sql` 新增 typed market observations：`twse_institutional_daily` 以 `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`，`trading_date DATE` 可為 NULL（UNAVAILABLE audit row），`provider VARCHAR(64) NOT NULL`、`source_url TEXT`、`observed_at TIMESTAMPTZ NOT NULL`、`source_available_at TIMESTAMPTZ`、`availability_basis VARCHAR(64) NOT NULL`、`status VARCHAR(20) NOT NULL`、`error_reason TEXT`，以 `UNIQUE(provider,observed_at)` 去重並建立 `(trading_date DESC,observed_at DESC)` index；不得宣稱 trading_date 是 PK/non-null。該 migration 同時在 `commodity_price_history` 增加 nullable `provider/source_url/source_available_at/fetched_at` 與來源時間 constraint。新增 `CandidateMarketFeature(code,value,asOfDate,availableAt,availabilityBasis,provider,sourceUrl,profileApplicability,duplicateOf,status,missingReason)`，只接 numeric adapter，不解析新聞文字。固定候選：

  | code / formula | source | conservative available-at / 適用性 |
  |---|---|---|
  | `IXIC_RET5/SOX_RET5/SPX_RET5/DJI_RET5 = 100*(close[t]/close[t-5]-1)` | `us_index_daily_history` | `tradingDate 18:00 America/New_York`；只取 `<=decisionInstant`。IXIC/SOX 若與既有 market regime 同義，`duplicateOf=MARKET_REGIME` 且不得直接 promotion；SPX/DJI 供 EQUITY candidate。 |
  | `INDEX_VOLUME_RATIO20 = latest positive volume / median(previous 20 positive volumes)` | TAIEX `trade_volume`（台股）或 IXIC volume（美股） | TAIEX `tradingDate 16:00 Asia/Taipei`；IXIC 18:00 New York。0/null 是 missing，不能冒充低量。 |
  | `TW_INSTITUTIONAL_NET_TURNOVER = totalNetAmount / same-date TAIEX trade_value` | 新表 `twse_institutional_daily(id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,trading_date DATE NULL,provider VARCHAR(64) NOT NULL,foreign_net numeric(20,2),trust_net numeric(20,2),dealer_net numeric(20,2),total_net numeric(20,2),source_url text,observed_at timestamptz NOT NULL,source_available_at timestamptz,availability_basis VARCHAR(64) NOT NULL,status VARCHAR(20) NOT NULL,error_reason text,UNIQUE(provider,observed_at))`，由 `TwseInfoFetchClient` 原始數值直接落地；`trading_date=NULL` 只代表 UNAVAILABLE audit row，不是 PK。 | `max(observed_at,tradingDate 16:00 Asia/Taipei)`；只適用台股 EQUITY。禁止從 `news_headline.title/summary` 反解析。 |
  | `WTI_RET5/BRENT_RET5/GOLD_RET5` 同 5-session return | `commodity_price_history` | 舊列以 `priceDate+1 day 00:00 America/New_York`、basis=`RECONSTRUCTED_CONSERVATIVE`；新抓取可用 fetched time。profile applicability 由 t308 分層。 |

  v1.96 同步為 `commodity_price_history` 增加 nullable `provider/source_url/source_available_at/fetched_at`，新列寫 provenance；舊列只能用上述保守重建邊界。`v1.97` provider/source 寬度為 128（snapshot provider 與 history source），`v1.98` 的同日 amount composite unique index 是 current-state migration，不改 append-only snapshot semantics。所有 candidate production contribution 預設 null，只有 t308 full-engine holdout 通過才寫具名常數。與 turnover/FX/MA/regime 代數或語意重複者 rejected/disclosure-only；一般新聞永不轉分數。
- [ ] **307.8 UI/匯出。** 展開列顯示 valuation composite 明細、ROE fallback、EPS trend、profile、下一配息與 market-aware public evidence。收合列不把新聞數量當信心分數。Excel/JSON/snapshot 同步欄位且 legacy 可讀。
