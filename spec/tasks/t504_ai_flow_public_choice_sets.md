# [t504] AI 判斷流程：公開候選決策分支與實際參數

**對應 Requirements:** Requirement 195（只依公開、明確記錄的工具候選集，顯示採用與未採用分支及實際已遮蔽參數）
**前置任務:** t501 已完成
**Liquibase changeset:** 無

## 背景

現行 AI 判斷流程只會保留實際工具呼叫。工具參數必須點選節點後才按需讀取，流程圖刻意不含參數。它沒有任何可被誠實還原的「未選擇」資料；從 LLM private reasoning、工具目錄、後續工具呼叫或靜態工作流去猜選項，會把推測誤呈現為事實，也會暴露不應保存的模型私有思考。

本任務把可視化的資料來源限定為 rollout 公開 function_call／custom_tool_call 的 payload.publicChoiceSet 所產生的 event.choiceSet。它不是 Chain-of-Thought 功能：上游未提供 payload.publicChoiceSet 的舊或新 run 必須維持 event.choiceSet 缺省的事實，不能重建 state、修改 payload、重新送出或虛構分支。

## 要做什麼

- [ ] **504.0 公開 producer 前置交付與精確 raw shape。** 本 repository 不實作或讀取 LLM private reasoning。唯一允許的 raw candidate source 是同一筆 `consumer=Codex`、`sourceKind=CODEX_ROLLOUT` public function_call 或 custom_tool_call payload 的 publicChoiceSet：它恰有 `schemaVersion="AI_FLOW_PUBLIC_CHOICE_V1"`、`publicSource="CODEX_PUBLIC_TRACE_EXPORTER"`、title、selectedOptionId、options；每一 raw option 恰有 optionId、label、toolName、input。`input` 只能是已由公開 trace exporter 審核並在同一公開 tool-call line 產生的單一 UTF-8 工具參數字串，不能是 object、array、nested envelope 或自由 reasoning 文本；collector 不遞迴解析它。這個欄位必須先由 asset-management 之外、已版本化的公開 Codex trace exporter release 寫入；沒有該 release 的真實 run 不會有候選，本任務只能在 UI 如實呈現「未記錄公開候選」。collector 只消費 raw field，不可從 private reasoning、assistant text、tool result、工具名稱／目錄、後續 event、固定流程或任何 heuristic 推測 choiceSet。每個 raw option.input 必須透過和實際工具 call 相同的單一 standardize/redact helper 產生 final parameters metadata。若同一 actual toolCall 已有 `sourceTruncated:true`，collector 必在讀 raw choice input 前省略整組 choiceSet，保留工具 event；不得以截斷候選假裝它和原實際呼叫逐欄相等。raw shape、schemaVersion／publicSource、input type、option count/id、selected relation、code-point 總長、private marker／reserved key 或 public-safe 檢查不合法時，collector 只省略該 choiceSet 且保留原工具 event；不得把不安全值改寫成候選、不得使工具 event 失敗或消失。
- [ ] **504.1 新增封閉、append-only 的公開候選契約。** 在 docs/openapi/ai-flow-observation-api.yaml、backend 與 bff 的 AiFlowDtos、AiFlowProtocol 及共用 fixtures 增加選填 ChoiceSet。observer version 從 1.2.0 升為 1.3.0。Event ingress 可省略 choiceSet，但明確 null、unknown field、deep unknown field、非 START event、沒有 toolCall 的 choiceSet，或 toolCall 有 `sourceTruncated:true` 的 choiceSet 全部回 400 INVALID_REQUEST。非缺省 choiceSet 同時要求 `consumer=Codex`、`sourceKind=CODEX_ROLLOUT` 和 AI-flow collector grant；Claude、schedule 與 consumer grant 皆固定 403、整筆 event 零寫入。ChoiceSet 必有 title（public-safe string，以 Unicode code point 計 1..100）、selectedOptionId（1..64，完整 TOOL_NAME pattern）與 options；options 為 2..8 items、optionId unique。每個 ChoiceOption 為 closed object，必有 optionId（同 pattern）、label（public-safe string，以 Unicode code point 計 1..100）、toolName（同 pattern）、parameters（Task 501 已清理文字）、parametersChars、truncated、redactedCount；唯一可省略欄位是 boxed Boolean sourceTruncated，存在時只能為 true。selectedOptionId 必存在，且該 option.toolName 必等於 Event.toolCall.name。每個 option 的 parameters 沿用 Task 501：raw input 與 choiceSet 合計先限制於 1,048,576 code points、憑證模式遮蔽、控制字元清理、16,384 code-point output cap、parametersChars 表示清理後截斷前長度、truncated 等價於原長超過 cap、redactedCount cap 為 100000、sourceTruncated 只表示 prescan 截斷。所有 option 的輸出 parameters 總和不得超過 32,768 code points。不得為 choiceSet 追加第二次 raw input/arguments 掃描。
- [ ] **504.2 collector 只接受公開欄位，永不推測。** 在 scripts/collect-srpp-ai-flow.py 只從同一筆公開 function_call／custom_tool_call 的 payload.publicChoiceSet 解析、清理與驗證資料，再把 final event.choiceSet 加入新的 START event 和該 event 的 collector state；private reasoning、assistant message、tool result、工具名稱、工具清單、後續 events、固定流程、payload.choiceSet、未知欄位都不能成為候選來源。collector 對 raw string 在標準化前只做 bounded code-point 計量和 private marker／reserved-key 拒絕，絕不把它 JSON parse 成 object/array 或掃描其他來源。既有 sources/codex-*.json、pending、ACK、DB event 絕不重算、更新、刪除、state reset 或 --replay。payload.publicChoiceSet 缺省或不合法時不得新增 event.choiceSet null key。擴充 scripts/tests/fixtures/ai_flow_tool_call_vectors.json 或建立等效跨語言 fixture，使 collector、backend、BFF 對 valid、null、非 object、unknown nested key、非 START、無 toolCall、少於兩項、重複 id、找不到 selected id、selected tool mismatch、false sourceTruncated、超額單項／合計參數、unsafe label/title、100／101 個 astral code point、巨大 string、deep object/array、nested private-reasoning canary、錯誤 consumer/sourceKind/grant 的接受或拒絕一致；並測 payload.choiceSet 不能被誤讀，保留 Task 501 toolCall 向量與舊 canonical payload 不變。
