# [t623] SRPP 衛星建倉腿：009826（張）與 VT（股）通用節奏計算

**對應 Requirements:** Requirement 220（台股日報 GLOBAL_EQUITY_PACE 由同 owner 已成交買進紀錄直接計算 009826 張數與 VT 股數建倉上限，並輸出 BUY 腿；與 SRPP `global_build_009826`／`global_build_vt` 逐欄等價）
**前置任務:** 無
**Liquibase changeset:** 無（只讀既有 `asset_transaction`、`exchange_rate_history`，不新增表或欄位）

## 背景

SRPP D-234（2026-11-22）把 VT 列為與 009826 同組的衛星建倉標的，兩檔都用「只計已成交、日／週／月額度、月內匯率減半、停止比重、誰先到就停」的固定公式。SRPP 目前在本機執行參考實作 `scripts/execution_policy.py` 的 `global_build_009826`（D-143／D-222）與 `global_build_vt`（D-234），9090 沒有對應的腿，日報規則寫明「9090未發布此腿前記`API_SCOPE_NOT_SUPPORTED`」。本任務把這兩支公式移入 asset-management，讓兩軌共用同一份計算結果。

**現在的錯誤行為：** `SrppReportModuleCalculator` 的 `GLOBAL_EQUITY_PACE` 模組（`new M("GLOBAL_EQUITY_PACE",...)`）只從 frozen extra 的 `global-pace` 來源讀 `stateBefore`／`confirmedFills`，再以 `SrppReportStateCalculator.paceAdvance` 與 `paceCapacity` 推進 VOO／009826 狀態。`global-pace` 這個 owner 來源在整個 repo 沒有任何 producer：`SrppReportExtraCaptureAdapter.capture` 最後一律把它寫成 `{"status":"UNAVAILABLE","reason":"GLOBAL_PACE_CANONICAL_SOURCE_UNAVAILABLE"}`。因此模組永遠落入 catch，只回 VOO／009826 原始 `monthlyBaseline`／`monthlyCap`、`missing=OWNER_BOUND_GLOBAL_PACE_STATE_AND_FILLS_UNAVAILABLE`、收據 `CONFIRMED_FILL_PACE_STATE_EVOLUTION=UNAVAILABLE`，且沒有任何 leg。VT 完全不在模組內。

**正確行為：** 009826 與 VT 的日／週／月消耗直接由同 owner、同代號、同市場的已確認買進交易（`asset_transaction`，即 `GET /api/public/transactions` 背後的帳本）計算，凍結成新的 owner-bound 來源；在模組中輸出 009826（台股、TWD、lots）與 VT（美股、USD、units）的 BUY 腿。不再依賴從未產生的 `global-pace` stateBefore（**推翻**009826 原本走 `paceAdvance` 狀態推進的做法：該狀態從未有來源，且口徑與 SRPP 參考實作不同）。VOO 的 225K 批次節奏、`global-pace` 來源、`paceAdvance`／`paceCapacity` 對 VOO 的行為完全不變。

腿只是**容量上限**，不是委託：D-188／D-205 高點閘、D-215 美元匯率偏好（Task 625）、雷達、五檔深度、去重、D-152 全行台幣買後底線（Task 624）仍留在各自位置；LLM 只可具名 WAIT／VETO，不得增減；券商只讀、不下單、不刷新、不寄信。

- [ ] 623.7 **009826 公式**（`global_build_009826` 逐步移植，順序即 reasons 順序）：

  2. 報價：`ask = quote.askLevels[0].price`（askLevels 為非空陣列且首元素為物件才取）；`identity = quote.stockCode=="009826" && quote.market=="台股" && quote.tradingDate==trading_date`。若 `finitePositive(ask)` → `basis="ASK1", reference=ask`（**即使 identity 不成立也先如此設定 basis**，與 Python 相同）；否則 `basis="LAST_PRICE", reference = identity ? quote.price : null`。`!identity || !finitePositive(reference)` → `QUOTE_UNVERIFIED`，`reference=null`。
  3. `!finitePositive(total_assets_twd)` → `TOTAL_ASSETS_UNVERIFIED`。`held_value_twd` 非（非 boolean 有限數值且 ≥0）→ `HOLDING_UNVERIFIED`。
  4. 節奏：`pace_ok = isoDate(selection.start) && isoDate(selection.end) && start <= min(month_start,week_start) && end >= trading_date && records 是陣列`。`pace_ok` 初始為 false 時**不走訪 records**（參考實作 `for r in (records if pace_ok else [])`），evidence 的 day／week／month 累計值皆為 0。逐筆：非物件 → `pace_ok=false` 繼續；`assetCode!="009826" || market!="台股" || transactionType!="買"` → 略過；`shares`、`amount` 須 finitePositive 且 `tradeDate` 須 isoDate，否則 `pace_ok=false` 繼續；`tradeDate > trading_date` 略過；`month_amount += amount`（tradeDate ≥ month_start）、`week_lots += shares/1000`（≥ week_start）、`day_lots += shares/1000`（== trading_date）。`!pace_ok` → `PACE_STATE_UNVERIFIED`。張數不四捨五入。
  5. 匯率減半：`rates = usdTwdRates 中 finitePositive 者`；`halved = rates 非空 ? max(rates) > fx_halving_threshold : true`；`factor = halved ? 0.5 : 1`；`cap = monthly_cap_twd×factor`，`baseline = monthly_baseline_twd×factor`。
  6. room（有序 map：day, week, month, weight）：`pace_ok` 時 `day = max_lots_per_day − day_lots`、`week = max_lots_per_week − week_lots`；`day < 1−EPS` → `DAILY_LOT_LIMIT`；`week < 1−EPS` → `WEEKLY_LOT_LIMIT`。`reference != null` 時 `lot_value = 1000×reference`、`month = (cap − month_amount)/lot_value`，且 `pace_ok && month < 1−EPS` → `MONTHLY_CAP`；若另 `finitePositive(total)` 且未記 `HOLDING_UNVERIFIED`：`weight = (stop_at_weight×total − held)/lot_value`、`post_buy_weight = (held+lot_value)/total`，`weight < 1−EPS` → `TARGET_WEIGHT_REACHED`。
  7. `lots = blocks 非空 ? 0 : max(min_k floor(room_k + EPS), 0)`；`lots>0 && finitePositive(total)` → `post_buy_weight = (held + lots×1000×reference)/total`。
