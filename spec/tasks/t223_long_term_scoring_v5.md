## 背景

### 使用者實際回報的問題

交易雷達的評分「明顯給短期強勢股高分、短期弱勢股低分，沒有考慮長期發展，尤其是個股」。經查證屬實，成因是結構性的。

### 現行 V4 的評分結構與失衡的量化證據

評分邏輯全部在 `backend/src/main/java/com/steven/assets/service/TradingRadarRuleEngine.java` 的 `evaluateStock()`（155–220 行）。現行實作為「基底 50 分 ＋ 各因子直接加減 ＋ 硬 clamp」：

```java
int score = 50;
score += priceVsMa(input.price(), input.indicators().ma20(),  8,  "月線", reasons, risks);
score += priceVsMa(input.price(), input.indicators().ma60(),  12, "季線", reasons, risks);
score += priceVsMa(input.price(), input.indicators().ma240(), 15, "年線", reasons, risks);
score += confirmationScore(input.ma20Confirmation(),  5,  "月線", reasons, risks);
score += confirmationScore(input.ma60Confirmation(),  8,  "季線", reasons, risks);
score += confirmationScore(input.ma240Confirmation(), 10, "年線", reasons, risks);
// KD：K>D 加 5、否則減 5；K>D 且 K、D 皆 <20 再加 3；K、D 皆 >80 減 3
// 大盤（僅 EQUITY）：RISK_ON +8、RISK_OFF −15
// 單日漲幅 ≥+5% 減 3、跌幅 ≤−5% 減 5
score = clamp(score);   // Math.max(0, Math.min(100, score))
```

依時間尺度歸類後的權重上限：

| 尺度 | 因子 | 上限 |
|---|---|---|
| 短期 | MA20 位置 ±8、MA20 確認 ±5、KD ±5（+3/−3）、大盤 +8/−15、單日漲跌 −3/−5 | **`+29 / −41`**（不對稱，下檔更重） |
| 中期 | MA60 位置 ±12、MA60 確認 ±8 | ±20 |
| 長期 | MA240 位置 ±15、MA240 確認 ±10 | **僅 ±25** |

**結構上短中期永遠壓過長期。** 實測 2026-07-17：

| 標的 | 現價 | MA20 | MA60 | MA240 | K/D | 單日 | 分數 | 建議 |
|---|---|---|---|---|---|---|---|---|
| 0050 元大台灣50 | 100.15 | 106.71 | 101.06 | **73.63** | 31.6/40.2 | −5.87% | 25 | 減碼候選 |
| 006208 富邦台50 | 227.75 | 242.80 | 229.66 | **167.26** | 32.9/42.4 | −6.08% | 25 | 減碼候選 |

兩檔現價都遠高於年線、長期位置分皆為正，卻因短期回檔被判減碼候選。

### 為什麼必須先修飽和才能加因子

逐項加總現行公式的極值：

```text
最大 = 50 +8 +12 +15 +5 +8 +10 +5(K>D) +3(KD<20) +8(RISK_ON)            = 124
最小 = 50 −8 −12 −15 −5 −8 −10 −5(K≤D) −3(KD>80) −15(RISK_OFF) −5(單日) = −36
```

理論值域 `−36 ~ +124`，硬 clamp 到 `[0,100]`。既有紀錄實測 `strongStock` 原始分達 **121**（該值域內的一個觀測值），超出上限的部分被 clamp 吃掉——**任何新增因子在強勢標的上等同沒有實作，且不會有任何錯誤訊息**。故飽和修正是本任務的前置條件，不是附帶優化。

### 本任務的解法：分數誠實，門檻分層

**不靠灌高分數解決問題。** 0050 的短期確實在跌（跌破月線季線、KD 弱、單日 −5.87%），分數理應偏低——用權重把它推高會讓分數失去短期預警的意義。改為讓**動作門檻**依長期趨勢組分數分層（詳見 223.5）。

### 本次修訂推翻了什麼

V4 的「基底 50 ＋ 直接加減 ＋ 硬 clamp」結構被推翻，改為分組加權正規化。V5 分數與 V4 分數**不可直接比較**。V3 的既有硬約束**全部維持不變**：還原權息同一價基、零 AI API、買進雙 `ABOVE` 硬閘門、`RISK_OFF`／stale 禁買閘門。

## 要做什麼

- [ ] **223.1 改為分組加權正規化（前置條件，須先完成再加新因子）**

  結構改為：

  ```text
  子因子 → 標準化為 [-1, +1] 的貢獻值（資料不足回 null，排除於平均之外）
  組分數 = 組內有效子因子的加權平均                  ∈ [-1, +1]
  score  = 50 + 50 × Σ(組權重 × 組分數)             ∈ [0, 100]
  ```

  因 `Σ(組權重) = 1` 且每個組分數 ∈ `[-1,+1]`，故 `Σ ∈ [-1,+1]`、`score ∈ [0,100]` **恆成立且無例外**。

  `clamp` **保留但改為防禦性斷言**。斷言的對象是 `Σ` 而**不是** `score`：

  ```text
  if (|Σ| > 1 + 1e-9)  → log.warn（權重或標準化有 bug）
  score = 50 + 50 × Σ，再 clamp(0, 100) 作為最後防線
  ```

  **`score = 0` 與 `score = 100` 是合法極值，不得因此告警。** 全部子因子皆 `−1` 且大盤 `RISK_OFF`（組分數 `−1`）時 `Σ = −1.00` → `score = 0`，恰好觸及下界，這是設計預期而非 bug。

  （上界不對稱：`RISK_ON` 只給 `+0.5`，故 `Σ` 的最大值為 `0.95` → `score = 97.5`，不會觸及 100。這個不對稱是刻意的，見 223.2。）

- [ ] **223.3b 短期動能組與中期趨勢組的子因子標準化定義**

  這兩組的子因子是從 V4 的加減分改寫而來，**標準化函數必須明確定義，不可由實作者自行推想**。

  | 組 | 子因子 | 標準化 |
  |---|---|---|
  | 中期 | MA60 位置 | 現價高／低於 MA60 → `+1`／`−1`，相等 `0` |
  | 中期 | MA60 兩日確認 | `ABOVE` `+1`／`BELOW` `−1`／`MIXED` `0`／`UNAVAILABLE` `null` |
  | 短期 | MA20 位置 | 同 MA60 位置（比照 MA240 的三態寫法） |
  | 短期 | MA20 兩日確認 | 同 MA60 兩日確認 |
  | 短期 | KD | 見下 |
  | 短期 | 單日漲跌幅 | 見下 |

  **KD 必須拆成「動能」與「位置」兩個正交子因子**（V4 為四路加減分：`K>D` +5／否則 −5；`K>D` 且 K、D 皆 <20 再 +3；K、D 皆 >80 −3——語意上錯誤，不得沿用也不得只是換算）：

  ```text
  KD 動能 = clamp((K − D) / 10, −1, +1)              短線轉強／轉弱，±10 即飽和
  KD 位置 = clamp(−(avg(K, D) − 50) / 50, −1, +1)     超買為負、超賣為正
  ```

  **為什麼一定要拆：** `K=90.8, D=86.0` 與 `K=26.1, D=20.7` 同樣是 `K>D`，但前者是「漲多了」、後者是「跌深反彈」，方向完全相反。任何把兩者壓進單一數值的設計都保留這個缺陷——實測若採「`base=(K−D)/10` 再對超買扣固定 `−0.3`」，`K=90.8／D=86.0` 得 `+0.48 − 0.3 = +0.18` **仍是正貢獻**，過熱依然沒被表達。拆分後：

  | 標的 | K / D | KD 動能 | KD 位置 | 語意 |
  |---|---|---|---|---|
  | 00719B | 90.76 / 86.01 | `+0.48` | **`−0.77`** | 轉強但嚴重過熱 |
  | 00679B | 26.10 / 20.70 | `+0.54` | **`+0.53`** | 跌深轉強 |

  **窄幅標的的 KD 位置必須失效**：`(hi9 − lo9) / lo9 < 2%` 時 KD 位置回 `null`（走組內重分配），**KD 動能不受此限**。理由：KD 量的是價格在 9 日高低帶中的位置，帶寬過窄時會在雜訊上飽和。實測 00719B 近 60 個交易日價格區間僅 `3.096%`、日報酬標準差 `0.217%`、**9 日高低帶平均寬度僅 `1.011%`**——其 `K=90.76` 實質只代表「比 9 日低點高 0.37 元」。把股票用的 80／20 閾值套在這種標的上屬指標誤用。閾值為具名常數。

  K 或 D 為 `null` 時兩個子因子皆回 `null`。兩者的 `clamp` 皆不可省略。

  **單日漲跌幅的標準化**（V4 為純扣分：`≥+5%` → −3、`≤−5%` → −5、其餘 0，**沒有正值區間**）：

  ```text
  changePercent >= +5%  → −1     （避免追高）
  changePercent <= −5%  → −1     （波動風險升高）
  其餘                   →  0
  ```

  **此子因子的值域刻意為 `[−1, 0]`，沒有 `+1`。** 語意是「單日異常波動是風險訊號」，雙向皆負是 V4 就有的設計（追高與急跌都扣分），本任務不改變這個語意。

  因此 223.13 的「全部子因子皆 `+1`」極端測試中，**此子因子的最大值為 `0`**，測試須據此計算預期分數，不得假設它能貢獻 `+1`。

- [ ] **223.4 缺值處理：權重重分配，嚴禁補 0（最容易做錯的一項）**

  子因子資料不足時**必須回 `null` 並排除於組內加權平均之外**；整組子因子皆為 `null` 時，**該組權重按比例重新分配給其餘有資料的組**，使實際生效權重總和恆為 `1`。

  以 `0` 代替缺值等同「給中性分」，會把資料不足的標的系統性拉向 50 分。實際受害者可枚舉：

  | 情境 | 缺什麼 |
  |---|---|
  | **本任務期間的全部標的** | 基本面組四項全缺（t224 才接線） |
  | 009804（僅 308 筆歷史，2025-04-16 起） | 3 年年化報酬（需 750 筆） |
  | 00929（753 筆，門檻 750） | 3 年報酬臨界 |
  | `BOND` 標的 | 大盤環境組 |

  基本面組全缺時，短期／中期／長期／大盤由 `0.22/0.18/0.30/0.10` 依比例放大為 `0.275/0.225/0.375/0.125`。

  （00919 有 905 筆，已滿足 750 門檻，是臨界值的對照組而非受害者。）

- [ ] **223.5 動作門檻依長期趨勢組分數分層（本任務解決原始問題的主要機制）**

  現行門檻定義於 `TradingRadarRuleEngine.actionFor()`（280–294 行）：

  ```java
  boolean buyGate = marketAllowsBuy
          && input.ma20Confirmation() == Confirmation.ABOVE
          && input.ma60Confirmation() == Confirmation.ABOVE;
  if (score >= 75 && buyGate) return input.held() ? Action.ADD_CANDIDATE : Action.BUY_CANDIDATE;
  if (score >= 55) return input.held() ? Action.HOLD          : Action.WATCH;
  if (score >= 40) return input.held() ? Action.HOLD_CAUTION  : Action.WAIT;
  if (score >= 25) return input.held() ? Action.REDUCE_CANDIDATE : Action.AVOID;
  return input.held() ? Action.EXIT_CANDIDATE : Action.AVOID;
  ```

  改為三層門檻表。**三層的區間必須互斥且窮盡**（端點歸屬明確，不得寫成 `≥ +0.5` 與 `−0.5 ~ +0.5` 這種在 `+0.5` 重疊的形式）：

  | 長期趨勢組分數 | 買進／加碼 | 續抱／觀察 | 警戒／觀望 | 減碼／迴避 |
  |---|---|---|---|---|
  | `> +0.5`（長期結構完好） | `75` | `55` | **`30`** | **`15`** |
  | `−0.5 ≤ x ≤ +0.5`（中性，**含兩端點**） | `75` | `55` | `40` | `25` |
  | `< −0.5`（長期轉弱） | **`85`** | `55` | `40` | `25` |

  雙向處理，完整回應原始訴求：長期完好時不因短期回檔被叫減碼；長期轉弱時不因短期反彈被叫買進。

  **長期趨勢組為 `null`（歷史不足）時一律套用中性層，不得套用寬鬆層。**

  門檻分層須為具名常數表，不得寫死於條件式。

  **這三層是設計常數，不是留給實作者依分數分布反推的自由參數。** 若讓實作者事後校準門檻，「特定標的不再是減碼候選」的驗收會變成循環論證（門檻調到過為止）。

  **`< −0.5` 層的買進門檻 85 在本任務期間不可達，屬預先定義。** 推導：本任務期間基本面組恆 `null`（權重 `0.275/0.225/0.375/0.125`），長期組為 `−0.5` 時的最大可能 `Σ = 0.275(1)+0.225(1)+0.375(−0.5)+0.125(1) = 0.4375` → `score ≤ 71.9`，連中性層的 75 都到不了。此層要到 t224 接上基本面組（`Σ` 上界提高到 `0.55` → `score = 77.5`）才會真正咬到。故本任務對該層的測試**須直接對門檻選擇函數做單元測試**，不得經由 action 輸出斷言（行為上區分不出來）。

  **驗算示例（用 006208，因為 0050 於 2025-06-18 有 1:4 分割，其長期因子須待 t225 完成才有正確值）**——006208 於 2026-07-17 的實測輸入：現價 227.75、MA20 242.80、MA60 229.66、MA240 167.26、K 32.9、D 42.4、單日 −6.08%，ETF 故基本面組 `null`，權重 `0.275/0.225/0.375/0.125`。

  ```text
  短期組 = 0.35(−1) + 0.25(−1) + 0.25(−0.95) + 0.15(−1) = −0.9875
           （KD：(32.9−42.4)/10 = −0.95，K、D 皆不在 <20 或 >80 故 bonus = 0）
  中期組 = 0.60(−1) + 0.40(−1) = −1
  長期組 ≈ +0.936    （MA240 位置 +1、確認 +1、年線斜率 +22.2% → +1、
                       52 週位置 +0.575、3 年年化報酬 +44% → +1）
  大盤組 = 0（NEUTRAL）

  Σ     = 0.275(−0.9875) + 0.225(−1) + 0.375(0.936) + 0.125(0) ≈ −0.146
  score = 50 + 50 × (−0.146) ≈ 43
  ```

  **注意 43 分這個案例證明不了分層有效**：43 在寬鬆層（減碼門檻 30）與中性層（減碼門檻 40）下**都是 `HOLD_CAUTION`**。把它從 V4 的 25 分（`REDUCE_CANDIDATE`）救起來的是**正規化**，不是分層。

  **分層真正做功的是大盤 `RISK_OFF` 的情境**：

  ```text
  Σ     = −0.146 + 0.125×(−1) ≈ −0.271
  score = 50 + 50 × (−0.271) ≈ 37

  套寬鬆層（長期組 0.936 > 0.5，減碼門檻 30）→ 37 ≥ 30 → HOLD_CAUTION
  套中性層（減碼門檻 40）                    → 37 < 40 且 ≥ 25 → REDUCE_CANDIDATE   ← 兩層輸出不同
  ```

  驗收分層是否生效，須以這類「兩層輸出不同」的輸入為準（見 223.13）。

- [ ] **223.6 買進硬閘門維持不變**

  `BUY_CANDIDATE`／`ADD_CANDIDATE` 仍須同時滿足：MA20 與 MA60 皆為 `ABOVE`（連續兩收盤日站上）、大盤非 `RISK_OFF`、大盤非 stale。

- [ ] **223.7 長期趨勢組子因子（本任務的新增因子，只用現有價格資料）**

  全部使用**還原權息序列**（與 MA／KD 同一價基）。既有硬約束不變：不得讓部分指標用還原值、部分用原始值。

  | 子因子 | 定義 | 標準化 | 資料需求 |
  |---|---|---|---|
  | MA240 位置 | 現價 vs MA240 | 高於 `+1`／低於 `−1`／相等 `0` | 240 根 |
  | MA240 兩日確認 | 既有 `confirm()` 結果 | `ABOVE` `+1`／`BELOW` `−1`／`MIXED` `0`／`UNAVAILABLE` `null` | 241 根 |
  | 年線斜率 | `(MA240(今) − MA240(60 交易日前)) / MA240(60 交易日前)` | `≥+5%` → `+1`、`≤−5%` → `−1`、線性內插 | 300 根，否則 `null` |
  | 52 週相對位置 | `(現價 − 52週低) / (52週高 − 52週低)`，映射 `(pos − 0.5) × 2`，**再 clamp 到 `[−1,+1]`** | 見左 | 240 根；分母為 0 回 `null` |
  | 3 年年化報酬 | `(現價 / 750 交易日前價)^(1/3) − 1` | `≥+15%` → `+1`、`≤0%` → `−1`、線性內插 | 750 根，否則 `null` |

  **52 週相對位置的 clamp 不可省略。** 52 週高／低取自完成日 K，而 `現價` 是 Redis 即時價（`TradingRadarService` 以 `priceQueryService.getLive()` 取得後併入序列）。創 52 週新高當日 `pos > 1` → 貢獻 > `+1` → 長期組分數 > 1 → 總分 > 100，正是本任務要修的飽和問題換個入口重現。**此路徑只在創新高當天出現，平時測不到，必須有專屬測試。**

  取數視窗須由現行的 241 根擴大為 **750 根**。現有 `stock_price_history` 實測 154,706 列／70 檔／2016-07 起滿 10 年，主流標的 2400+ 筆，容量無虞。

  **擴大視窗前 t225 必須已完成。** 現行的 241 根視窗恰好落在 0050 的 1:4 分割（2025-06-18）之後，所以 V4 從未踩到「還原服務不處理分割」這個既有缺陷；擴大到 750 根會跨過分割，使該標的的 3 年年化報酬與年線斜率算出方向相反的值且不拋例外。

  **另須排除 `close_price <= 0` 的列**（實測台股有 176 筆）。這些列會造成 3 年報酬除以零、52 週高低取到 0 而使相對位置恆為 `+1`。排除後若有效根數不足該因子門檻，該因子回 `null`（走權重重分配），不得以剩餘資料硬算。此排除邏輯由 t225 一併實作於還原服務，本任務只需確認取數後的序列已無非正收盤。

- [ ] **223.10 可解釋性**

- [ ] **223.13 測試**

  測試與實作同屬本任務，不得延後。至少覆蓋：

  - **不再飽和**：全部子因子取各自的極大值、極小值，**以及各自疊加 `RISK_ON`／`RISK_OFF`** 的極端輸入，分數落在 `[0, 100]` 且未觸發 `|Σ| > 1` 的 WARN。（疊加 regime 這一項是關鍵——它會抓出「把 regime 寫成正規化後調整項」的錯誤實作。）
    - 計算預期值時注意**單日漲跌幅子因子的值域是 `[−1, 0]`**（見 223.3b），全正極端輸入時它是 `0` 而非 `+1`。
    - `score = 0`（全負 + `RISK_OFF`）是合法極值，**不得**斷言為 WARN。
  - **KD 標準化的越界防護**：`K−D ≥ 10` 且 `K、D 皆 < 20` 時（`base = +1`、`bonus = +0.3`），經 clamp 後貢獻為 `+1` 而非 `1.3`。
  - **52 週位置的開放區間**：現價 > 52 週高（創新高當日）時，經 clamp 後貢獻仍為 `+1`，總分不超過 100。
  - **權重重分配**：任一組全 `null` 後實際生效權重總和為 `1`；基本面組全 `null` 時四組為 `0.275/0.225/0.375/0.125`；`BOND` 的大盤組 `null` 亦觸發重分配。
  - **除以零與負基期**：52 週高低相等回 `null`，不得回 `+1` 或拋例外。
  - **新掛牌標的**：< 750 筆歷史時 3 年報酬回 `null` 且不影響長期組其餘四個子因子。
  - **門檻分層邊界（直接測門檻選擇函數，不經 action 輸出）**：長期組 `= +0.5` 套**中性層**、`= −0.5` 套**中性層**（端點歸中性層，見 223.5 的互斥區間定義）、`= +0.51` 套寬鬆層、`= −0.51` 套嚴格層、`= null` 套中性層。
    - `< −0.5` 層的 85 買進門檻在本任務期間不可達（見 223.5 推導），故該層**只能**用門檻選擇函數的單元測試驗證，不得用 action 輸出斷言。
  - **分層確實改變輸出**（證明分層有作用，而非只是存在）：構造一個落在兩層門檻之間的分數（如 37 分、長期組 `0.936`），驗證套寬鬆層得 `HOLD_CAUTION`、強制套中性層得 `REDUCE_CANDIDATE`——**兩者必須不同**。若某測試在兩層下輸出相同，它就證明不了分層生效。
  - **硬閘門未被繞過**：分數再高但 MA20 確認為 `MIXED` 時仍不得產生 `BUY_CANDIDATE`／`ADD_CANDIDATE`；大盤 `RISK_OFF` 與 stale 時同樣禁買。
  - **結構性迴歸判準**（取代釘死特定標的動作的循環論證）：固定其他輸入、僅將長期趨勢組分數由 `−1` 掃到 `+1`，總分須**單調遞增**，且變動幅度 **≥** 短期動能組做同樣掃描時的變動幅度。
  - **觀測記錄**（非驗收條件）：輸出全部台股標的的 V4／V5 分數與動作對照表，附於完成報告。
