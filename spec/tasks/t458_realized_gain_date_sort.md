# [t458] 已實現損益明細依交易日期雙向排序

**對應 Requirements:** Requirement 167（已實現損益頁的交易日期欄可由較早到較晚或較晚到較早排序）
**前置任務:** 無
**Liquibase changeset:** 無

## 背景

已實現損益頁的明細表目前以一般文字呈現「交易日期」，使用者無法依日期快速整理已載入的紀錄。頁面資料已有年度卡片與市場分頁篩選，排序應套用在這些篩選後的列，並只改變畫面順序。

## 要做什麼

- [ ] 458.1 在 `RealizedGainView` 將「交易日期」欄設為自訂可排序欄，點上箭頭直接套用 `ascending`、下箭頭直接套用 `descending`；點擊已作用中的箭頭不可清除排序，並同步保留方向圖示。這是一般「排序／篩選由 BFF 處理、前端只呈現」分層規範中的限縮純顯示例外，只對已載入且已經年度／市場篩選的可見列暫時排序，不變更 BFF 回傳或資料語意。
- [ ] 458.2 新增純函式日期排序 helper，依 ISO `YYYY-MM-DD` 完整日曆日期比較。回傳新陣列，不修改輸入；降冪反轉日期比較方向，同日固定依原始索引由前至後，禁止反轉整個升冪排序結果。自訂排序只作用於目前年度與市場篩選後的列，不改變統計、年度摘要、匯出、編輯／刪除／雙擊行為，也不保存排序狀態。
- [ ] 458.3 新增前端單元測試並將其加入既有 `npm test` 指令，覆蓋跨年升冪／降冪、同日穩定順序、輸入不變、上／下箭頭方向接線，以及 Element Plus 回報 `order: null` 時仍保留既有方向並恢復圖示狀態。
- [ ] 458.4 不新增或修改 API、BFF、DTO、資料庫、券商呼叫、外部服務或交易功能。

## 驗證

在專案根目錄執行：

```bash
cd frontend && npm test
cd frontend && npm run build
```

另依 `.agents/skills/run-stack/SKILL.md` 的流程重建並重新建立 `frontend` 容器，在已實際載入的已實現損益頁分別點擊「交易日期」上箭頭與下箭頭，確認升冪／降冪方向正確；重點目前作用中的箭頭後，排序與作用中圖示仍維持，不得清除或回到原始列順序。年度與市場篩選、總額、其他列操作與匯出範圍維持原行為。
